Help

How this app works
For each character/course: search or paste a GameBanana link, download the file(s) you want, then check them under "Mods to merge." Once everything you want is checked, press the Next button (bottom right) or open the Commit step in the bar at the top - it combines every checked mod's files into one romfs tree (plus any checked code patches, under atmosphere/exefs_patches/) at sd-card-staging/, next to your master directory, ready to copy onto your SD card's existing atmosphere/ folder.
The five steps
The bar at the top always shows where you are: 1 Setup (your game version, options and language - reopen it any time), 2 Choose mods (the Character, Course, Vehicles, More and Full List tabs), 3 Commit (puts every ticked mod's files together and lets you settle any clashes), 4 UI icons & text (builds the combined menu pictures and names), and 5 Copy to Switch (a short checklist). A green tick means that step is done; an amber number means something changed and it needs another look. The Next button in the bottom-right corner always says what to do next.
Menu look: icons and names
Every character and course popup has a Menu look card showing what the menus will display for it - the character-select, map and results icons, and its name - and where each comes from (a mod, you, or unchanged). If a mod doesn't ship an icon or a new name, you can add your own: pick one of the mod's screenshots or a picture from your computer, drag the square over the part you want, and it becomes all three icons; or type a name. These are combined into the menu files in step 4, exactly like a mod's own changes.
Voice: mute a line or use your own sound
Every character's card has a Voice row with Edit voice lines. It lists what the character says - character select, finishing first / mid-pack / last, overtaking, getting hit, items, boosts, the horn - each with a short description (some marked guess: play it to check). For any line you can Mute it, or Use my own sound: choose an audio file (mp3, wav, ogg, m4a...), pick the part you want, and the app converts it to the game's format (up to 8 seconds). Each line is really several sounds in the game's file (variations and tails); they are always changed together.

The row is greyed out until the character has a ticked mod, like Name and Icons. The result is saved as a mod called Custom voice under that character - tick, untick or remove it like any other, and Commit merges it. Changing one line means writing out the character's whole voice file, so the app starts from the voice you'd otherwise get: a voice mod you've ticked for that character, or else the game's own file (choose your game's files folder in Settings). If you tick a different voice mod later, your changes move onto it.
Known issues
A modded course feels like it's playing in slow motion
This is a real, named phenomenon in Mario Kart track modding - the "Slow Motion Bug." The game's physics tick is tied to frame rate, so when a track's geometry/collision/effects exceed what the CPU/GPU can process per frame, the whole race visibly slows down instead of just stuttering. It's especially common in tracks ported from a different game's engine (e.g. an Arcade GP DX or Mario Kart Tour port) since the source assets were never built under MK8DX's performance budget. There's no fix on this app's side - it's a property of the mod's own geometry/collision data, not a merge conflict or a missing file. See the Custom Mario Kart wiki's Slow Motion Bug page for the full technical breakdown.
A modded course's select-screen icon or results-screen background is missing
Most course mods bundle their own UI/cmn/menu/ym_CoursePict_<internal id>.bntx thumbnail and UI/cmn/ending/ym_AwardBG_<internal id>.bntx results background, uniquely named per course - these are now merged in normally like any other file (fixed - older merges from before this fix won't have them; commit again to pick them up). If a mod genuinely doesn't bundle one, open that mod's card and use "Icon from screenshot" to generate one from its own GameBanana screenshots instead - see the Course Select strip, which previews any icon (bundled or generated) inline so you can see at a glance which courses still have none. (The black border around every icon, including generated ones, is intentional - it matches the real game's own template, which reserves that space for the course name text drawn over it - see the README for exactly how that was measured.)
A modded character's icon or a modded course's name still looks vanilla
Icons and names live in three shared game files (common.sarc, menu.sarc, message.sarc) that every mod ships its own copy of, so a commit can't combine them. Open the UI icons & text step (step 4 in the bar at the top, or the Next button after committing) - it works out what each mod changes, builds the combined files for you, and checks them.
A modded course's name still shows the original vanilla name
The display name comes from a locale-wide message.sarc file that packs every menu string - including every course's name - into one shared table. A mod's own copy of it is never merged in (same reasoning as common.sarc/menu.sarc for character icons - it would silently wipe out every other string not present in that mod's own rebuild), so a stock course name is expected even after its geometry, textures and icon are fully modded. Changing it requires hand-injecting the new string into a combined message.sarc with a tool like Switch Toolbox - this app can't safely automate that.
File status glossary
Downloaded
Extracted successfully and found at least one usable romfs mod - ready to check under "Mods to merge."
UI art only
UI art (PNG/texture icon sets) or a packed common.sarc/menu.sarc, with no romfs folder - not a mergeable romfs mod. See "UI Icon Worklist" in Settings for what to do with these.
Code patch (badge on a mod)
An exefs patch (.ips files named after a game build id) that patches the game's executable instead of adding romfs files - most Mechanics mods are this. Commit copies it to atmosphere/exefs_patches/ in the staging folder (never selected by "Select All" - tick each one yourself). It only works on the exact game version it was built for and does nothing, silently, on any other; set your game's build ID in Settings to be warned about mismatches. Two patches that overwrite the same bytes conflict and can't both be checked.
Packed archive only (badge on a mod)
The mod has a romfs, but everything in it is a packed .sarc (common/menu/message) - a commit never copies those in, since they'd overwrite every other icon or text entry. On its own, ticking it does nothing - it takes effect through the UI icons & text step.
Missing romfs wrapper
Extracted, but the mod folders (Driver/Kart/Audio/...) sit at the top level instead of under a "romfs" folder - create a "romfs" folder there and move them into it.
Needs manual fix
The archive extracted, but nothing about its layout was recognized - open its folder and check what's actually inside.
Slot / music mismatch warning
A course mod's bundled content (or race music) matches a *different* course's known internal id than the one you downloaded it for - it may belong under a different course's row instead.
Conflicts & left-out files
A conflict (a "clash") means two ticked mods write genuinely different content to the same file - byte-identical coincidences don't count. You settle each clash on the Commit step (or from a mod's popup) with one click: keep one mod's version, use the game's own files, or untick a mod. Either way only the clashing files are affected - the rest of each mod still works. Behind the scenes that just means those files are "left out" of one mod; every mod's popup has a Files button to see everything it ships and leave out any single file yourself, and Settings lists every leave-out with an "Include again" button. Choices are remembered, even across re-downloads. Two code patches that overlap can't be split like this - one of them has to be unticked.
Where your files live
mods/downloads/<category>/<item>/ holds the raw downloaded archives, one folder per character/course. mods/extracted/<category>/<item>/<mod name>/romfs/... is what those unpack to - this is what actually gets scanned for "Mods to merge." ui-icons/romfs/... is your own hand-merged combined character-select icon set, always included and never part of the checklist. Audio/Static/BGM.bars is never taken from any mod - it's a shared, game-wide file, not a per-course one, and is the single biggest source of unnecessary cross-course conflicts.

Settings

Master Directory
Where this app keeps your downloads and all its own settings/cache files. Changing it lets you optionally bring your existing files along to the new folder.
UI icons & text
UI Icon Worklist
Every downloaded mod that's UI art or a packed .sarc with no romfs (character icon sets, loading-screen/theme archives, ...) - can't be merged automatically. Use an external tool like Switch Toolbox to inject the icons into your combined set at ui-icons/romfs/UI/cmn/. A whole-file .sarc from a theme is a full replacement of that set, so start from it deliberately rather than layering it over your own icon work.

Game version
Code patches (exefs .ips files, e.g. most Mechanics mods) only work on the exact game version they were built for, and do nothing - with no error - on any other. Enter your game's build ID (the name of its .ips patch files / cheat files, found on cheat databases for your version) to have patches for a different version flagged as "wrong game version". Leave empty to skip the check.
Your game's files (for menu icons & names)
GameBanana Browsing
When off, mods GameBanana marks with a content visibility rating are hidden from "Browse GameBanana" results. Pasting a direct link to a specific mod always works regardless of this setting.
Character Select
Off by default. When on, each character tile shows a badge like 1/4 (mods ticked / mods downloaded). When off, a tile that has mods downloaded but none ticked gets a small hollow ring instead, and hovering a tile still tells you the numbers.
On by default. Each time you click a character's tile, and when a character's mod becomes finished (its name and icons checked, or nothing to check), the app plays the character-select voice from its ticked mods - the sound the game makes when you pick it - and the speaker on its tile lights up while it plays. Nothing plays for a character whose mods don't include one.
Advanced
Shows extra technical detail (for example the full list of files in a conflict is open by default). Nothing essential is hidden without it - conflicts and left-out files are always available in the section below.
Conflicts & left-out files
When two checked mods change the same file you can keep one mod's copy, use the game's own file, or leave just those files out of one mod - the rest of the mod still works. Leave-outs are remembered, even across re-downloads, and every mod's popup has a "Files" button (in a character's mod list it is "Edit included files" in the row's ... menu) to leave out any single file.
